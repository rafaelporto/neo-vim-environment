# Editing Tools

Small utility plugins configured across several `after/plugin/` files.

## Comment.nvim

Configuration in `after/plugin/comment.lua`. Bare `setup()` call — uses default keymaps.

| Key | Mode | Action |
|---|---|---|
| `gcc` | n | Toggle line comment |
| `gc` + motion | n | Comment motion (e.g. `gcap` = comment paragraph) |
| `gc` | v | Toggle comment on selection |

## vim-surround

`lazy = false`. Standard tpope surround bindings.

| Key | Action |
|---|---|
| `ys{motion}{char}` | Add surround |
| `cs{old}{new}` | Change surround |
| `ds{char}` | Delete surround |

Example: `ysiw"` surrounds word with quotes; `cs"'` changes `"` to `'`.

## Undotree

Configuration in `after/plugin/undotree.lua`. Persistent undo stored in `~/.vim/undodir` (set in `set.lua`).

| Key | Action |
|---|---|
| `<leader>u` | Toggle undotree panel |

## Todo Comments

Configuration in `after/plugin/todo-comment.lua`. Highlights `TODO`, `FIXME`, `HACK`, `NOTE`, `BUG`, `PERF`, `WARN` in comments.

| Key | Action |
|---|---|
| `ntd` | Jump to next TODO comment |
| `ptd` | Jump to previous TODO comment |
| `<leader>td` | List all TODOs in Telescope |

> `<leader>td` used to collide with neotest's debug-nearest-test. neotest moved to `<leader>tD`, so this key is unambiguously the TODO list. See [neotest.md](neotest.md).

## Treesitter

Two files own this: parser installation lives in the `nvim-treesitter` spec in `lua/default/plugins.lua`, highlighting and folds in `after/plugin/treesitter.lua`.

### What nvim ships — and what it does not

nvim 0.12 ships the treesitter **API** (`vim.treesitter.start()`, `vim.treesitter.foldexpr()`, incremental selection) but only **7 parsers**: `c`, `lua`, `markdown`, `markdown_inline`, `query`, `vim`, `vimdoc`. There is no `vim.treesitter.install` (the field is `nil`), no `:Treesitter` command, and none is planned for 0.13.

> Previous versions of this document claimed nvim 0.12+ ships parsers bundled and that `nvim-treesitter` was not needed. That was false — outside those 7 filetypes there was no parser, so no treesitter highlighting, no treesitter folds and no rainbow delimiters.

### nvim-treesitter (branch `main`)

`master` is frozen and does not support nvim 0.12, so the spec pins `branch = "main"`. After the rewrite the plugin is **only a parser installer and query provider** — it does *not* do highlighting.

| Detail | Value |
|---|---|
| `branch` | `main` |
| `lazy` | `false` — upstream: "this plugin does not support lazy-loading" |
| `build` | `:TSUpdate` |
| `setup()` | Optional, and accepts only `install_dir` (default `stdpath("data")/site`) |
| `ensure_installed` | **Gone** — does not exist on `main` |
| Install call | `require("nvim-treesitter").install({ ... })` in the spec's `config` |

`install()` is asynchronous and a no-op for parsers already present, so it is safe on every startup.

### Commands

| Command | Action |
|---|---|
| `:TSInstall {lang}` | Install a parser |
| `:TSInstallFromGrammar {lang}` | Install from a local grammar |
| `:TSUpdate` | Update installed parsers |
| `:TSUninstall {lang}` | Remove a parser |
| `:TSLog` | Open the install/build log |

### Installed parsers

32 parsers are installed into `stdpath("data")/site/parser` (the 7 nvim ships are in the list as well, so the site copy wins):

`bash`, `c`, `c_sharp`, `css`, `dart`, `diff`, `dockerfile`, `gitcommit`, `gitignore`, `go`, `gomod`, `gosum`, `gowork`, `html`, `javascript`, `jsdoc`, `json`, `lua`, `luadoc`, `markdown`, `markdown_inline`, `query`, `regex`, `scala`, `sql`, `swift`, `toml`, `tsx`, `typescript`, `vim`, `vimdoc`, `yaml`.

### Host prerequisites

- A C compiler, `curl` and `tar`.
- [`tree-sitter-cli`](https://github.com/tree-sitter/tree-sitter) 0.26.1+ — `brew install tree-sitter-cli`. **Required**, not optional: grammars that ship no pre-generated `parser.c` (the `swift` one among them) have to be generated by the CLI before they can be compiled.

### Language registration

Filetypes without a parser of their own reuse a compatible one:

| Filetype | Parser |
|---|---|
| `jsonc`, `json5` | `json` |
| `zsh` | `bash` |

### Highlighting autocmd

`after/plugin/treesitter.lua` registers a `FileType` autocmd (augroup `ts_highlight`) that:

1. **Returns early if `vim.treesitter.highlighter.active[buf]` is already set.** Native ftplugins call `vim.treesitter.start()` themselves for `lua`, `markdown`, `help` and `query`; without this guard those buffers would get a *second* highlighter attached on top of the first.
2. Resolves the language with `vim.treesitter.language.get_lang()` and pre-checks it with `vim.treesitter.language.add()`. `add()` returns `false` plus a message when the parser is missing instead of throwing, so no `pcall` is needed — which means a real error out of `start()` is not swallowed either. The old code wrapped everything in a blanket `pcall`.
3. Calls `vim.treesitter.start(buf, lang)` and then sets treesitter folds window-locally: `foldexpr = v:lua.vim.treesitter.foldexpr()` and `foldmethod = expr`.

> **Why `foldlevel` is 99:** because that autocmd sets `foldmethod=expr`, the default `foldlevel` of 0 would open every file with everything folded. `set.lua` sets both `foldlevel` and `foldlevelstart` to `99`.

## Rainbow Delimiters

Configuration in `after/plugin/rainbow-delimiters.lua`. Colors nested brackets/parens/braces with a 7-color cycle.

| Option | Value |
|---|---|
| Default strategy | `global` |
| Vim files strategy | `local` |
| Default priority | 110 |
| Lua priority | 210 |

Colors (in order): Green → Yellow → Blue → Violet → Cyan → Orange → Red.

> Rainbow delimiters needs a parser for the buffer's language. With only nvim's 7 bundled parsers it was silently inert in Go, TypeScript, Dart, JSON and every other language; re-adding `nvim-treesitter` is what made it work there.

## nvim-ts-autotag

Auto-closes and auto-renames tag pairs (`<div>` → `</div>`) in JSX/TSX, HTML and Markdown. Declared in `lua/default/plugins.lua`.

| Detail | Value |
|---|---|
| `ft` | `html`, `javascript`, `javascriptreact`, `typescript`, `typescriptreact`, `markdown` |
| `opts` | `{}` |

> **`opts = {}` is mandatory, not decoration.** It is what makes lazy.nvim call `setup({})`. Without an explicit setup the plugin takes its zero-config path, which does `require("nvim-treesitter.configs")` (`internal.lua:460`) to read a legacy `autotag` module — a module that does not exist on branch `main`.

## vim-illuminate

`lazy = false`. Automatically highlights all other occurrences of the word under the cursor using LSP, Treesitter, or regex (in that priority order). No configuration or keymaps needed.
